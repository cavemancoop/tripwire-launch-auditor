## 2. Item 4 — the session push. NOT BUILT.

**What exists:** `apps/worker/src/scripts/railway-push-env.ts`
(`pnpm railway:push-env`). Pushes `ORBIO_API_KEY` (from the encrypted token
store) plus `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHANNEL_ID` /
`TELEGRAM_ALERTS_CHANNEL_ID` (from `.env`) into a Railway service in one call.
Prints fingerprints only, keeps values out of shell history, supports
`--dry-run`, `--service`, `--only`. Verified working — this is what turned
deep-dives and the feed on.

**What does not exist — nothing was written for any of this:**
- No `--with-session` flag. Confirmed: zero matches for `with-session`,
  `TOKEN_STORE_B64`, `tokenStoreSeed` in `railway-push-env.ts` or `index.ts`.
- No worker-side seeding: nothing reads an encrypted store out of an env var
  and writes it to disk at boot.
- No `pnpm orbio:auth --push`.

**Design intended (not code):** push the encrypted token store as a base64 env
var; the worker writes it to the store path at boot **only when no store file
exists**, so it can never clobber a live local one; ship as
`pnpm railway:push-env --with-session` so the routine key/Telegram push stays
separate from pushing a session.

**Decision this raises, unresolved.** The token store is a materially different
secret from the gateway key: the key only spends against a capped balance, the
store can mint and revoke keys through the MCP. It is encrypted with
`TOKEN_ENCRYPTION_KEY`, which is *already* on Railway — so both halves would sit
in one place and secret separation is genuinely reduced. That should be a
DECISIONS.md line, like the gate change was, not a silent implementation detail.

## 4. Open decisions

- **Property 2 visibility.** The Orbio gateway exposes no key/usage/credits/
  balance endpoint — 14 paths probed, all return the same HTML catch-all while
  `/api/v1/models` returns real JSON. `/api/key` returns **405 not 404**: the
  route exists but rejects GET, almost certainly the POST behind
  `orbio_create_key`, deliberately not probed because that call mints *and
  retires* the active key. So balance is readable only with a live MCP session.
  With no session in production, `trailingCreditsUsd` is null **100%** of the
  time — not 1-in-24. Property 2 is therefore only demonstrable during the
  session window, and the panel must say which. This is why item 4 precedes it.
- **Session secret on Railway** — see §2.
- **SELL_IMPAIRED** — resolved for now as descriptive-only (it measures
  liquidity depth, not deception; no notional fixes that, since 2% of a thin
  pool still moves the price). Resizing resets the cell's record, so it waits
  until after judging.
